# research — generation, solving, difficulty

Turning the game into an instrument: generate a level from a seed, have a bot
play it, and decide whether it is solvable and how hard it is.

The governing rule is that **the bot must play the game that ships**. Anything
that re-implements the physics creates a second, subtly different game, and then
"solvable" means nothing. So the harness boots the real Phaser game with the
renderer switched off and steps it by hand. `src/` stays the game; nothing in
here forks it.

```bash
npm run sim:spike        # boot headless, benchmark steps/sec
npm run sim:determinism  # assert two identical runs stay identical
```

Everything needs `node --import ./research/harness/register.mjs`, which installs
the DOM shims and the module hook *before* Phaser is imported. Phaser reads
`window` while its module body evaluates, so this cannot be a plain import.

## Phase 0 result

The real game boots headless in ~17 ms and runs at **~151,000 steps/sec**,
about **2,500× real time**, single-threaded on this machine. The exit criterion
was 500/sec, so search has a budget roughly 300× larger than the plan assumed.

Getting there meant making the simulation reproducible, and three separate
things were secretly running on wall-clock time. Each one produced small
position drift that would have quietly invalidated every result downstream.

**1. requestAnimationFrame kept stepping the game.** `game.loop.stop()` has to
happen after `game.isRunning`, not after `game.isBooted` — the loop does not
exist yet at boot, so stopping it there stops nothing and it comes up anyway.
`bootHeadless()` now asserts the loop really is stopped rather than trusting it.

**2. Phaser's TimeStep smooths its delta.** It derives delta from the wall clock
and averages it over recent frames, so the value a scene sees depends on when
the process happened to call in. The harness drives `Game.step(time, delta)`
directly and supplies the delta itself.

**3. The TweenManager runs on `Date.now()`.** This one is worth knowing about if
you ever step Phaser anywhere. `TweenManager.getDelta()` reads
`Date.now() - prevTime` *by design*, so tweens keep real-world pace whatever the
frame rate — and that makes them structurally incompatible with a stepped
simulation. In a tight loop they advance by microseconds and effectively freeze.

That is not cosmetic. `Player.squash()` scales the sprite, an Arcade body scales
with its game object, so a frozen squash left the collider **12.8px tall instead
of 16** — permanently, and differently per run. Collision itself diverged from
the browser. The harness advances a synthetic `Date.now()` in lockstep with the
fixed step, so the real tween code runs untouched and lands on the same values
the browser produces. The visible symptom of the fix: the player settles at
y=996 instead of y=998.4.

## Fidelity notes

- Phaser is loaded from `dist/phaser.esm.js` — the same prebuilt bundle Vite
  resolves for the browser — so the harness and the game run identical engine
  code. The package `main` field points at `src/`, which needs a WebGL debug
  dependency that is not installed and never used.
- `BootScene` runs **unmodified** against a real canvas (`@napi-rs/canvas`), so
  textures and animations are generated by exactly the code the browser runs.
  There is no second art pipeline to drift.
- Phaser's `HEADLESS` mode leaves `game.renderer` null but its own
  `CanvasTexture.refresh` dereferences `renderer.gl` unguarded, so a null-object
  renderer stands in. Booting the CANVAS renderer would also work, but then
  every simulated step rasterises a frame nobody looks at.
- The one change to `src/` so far is `import.meta.env.DEV` → `import.meta.env?.DEV`
  in three files, because that Vite-ism is undefined outside the bundler. The
  production bundle hashes identically before and after, so the shipped game is
  byte-for-byte unaffected.

## Still to prove

Determinism is checked run-to-run *within* Node. The parity test in Phase 1 —
replaying a recorded browser input sequence headless and comparing trajectories
frame by frame — is what will show the headless sim matches the *browser*, which
is the claim the whole project rests on.
